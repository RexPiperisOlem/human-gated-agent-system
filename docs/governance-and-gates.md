# Governance and Gates

## Human authority

The system owner remains the final authority. Agents can classify, draft, check, recommend, and record. They cannot convert their own recommendation into permission.

## Gate levels

### `INTERNAL`

Permitted reference actions include reading supplied material, extracting fields, classifying, drafting, comparing, and creating a proposed record. These actions must remain inside the authorized working area.

### `REVIEW`

A human must confirm the record before the next stage. Use this level when classification, scope, public wording, release status, or source interpretation materially affects later work.

### `ACTION`

A human must explicitly authorize the exact action, target, and scope immediately before execution. Examples include publishing, sending, purchasing, changing an account, moving an original file, or making a public commitment.

### `BLOCKED`

The reference system does not automate this action. Typical examples include irreversible deletion, disposal of unique objects, unsupervised bulk file movement, and unreviewed high-stakes submissions.

## Approval rules

- Approval expires when the target, content, destination, or material risk changes.
- Approval to prepare is not approval to execute.
- Silence is not approval.
- A previous approval is not blanket authority for a later action.
- Agents must record assumptions and unresolved questions beside the proposed action.
- A human override should be recorded with the reason when it changes a gate decision.

## Data handling

- Supply the minimum data required for the current agent.
- Keep private source material outside the public repository.
- Use references or stable identifiers instead of copying sensitive content into every handoff.
- Do not put credentials, access tokens, private keys, or authentication cookies into prompts or records.
- Define a retention and deletion policy before processing real personal or customer data.

## High-stakes domains

This repository is not legal, medical, financial, conservation, or safety advice. Domain work requires qualified review, current authoritative sources, and project-specific controls.
